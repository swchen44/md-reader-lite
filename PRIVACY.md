# Privacy Policy — MD Reader Lite

_Last updated: 2026-10-24_

MD Reader Lite renders Markdown files locally in your browser.

**Mermaid and ZenUML:** Both engines, fonts and settings styles use bundled code or local system fonts, with no CDN or rendering server. Mermaid runs in an extension-local frame with its own restrictive CSP. Structured input checks reject resource-bearing markup/CSS and native diagram styles before rendering; returned SVG/CSS is sanitized and scoped. Unsupported resource syntax stays as readable source. This Mermaid-specific boundary does not close the existing arbitrary-document HTML/CSS sweep gaps disclosed below. Runtime gates and limitations: [Mermaid migration test plan](docs/superpowers/plans/2026-10-23-mermaid-modernization.md).

- **Offline mode, on by default.** Blocks auto-refresh, GitHub API directory browsing and PlantUML. After rendering, it removes supported absolute HTTP(S) and protocol-relative media attributes from the document. Same-server Files-tab requests remain allowed; local `file://` features keep working. Network-listener tests cover specific fixtures, not every possible document. Relative media URLs on HTTP(S) pages and arbitrary document CSS remain outside this sweep, as explained below.
- **Zero network by default, feature by feature.** With offline mode off, auto-refresh, charset compatibility, and PlantUML are each still individually **off by default**. The folder tree tab is **on by default** — that's a visibility setting, not a network one; the directory listing itself is still lazy and nothing is fetched until you actually open the Files tab. **Opening the Files tab on a same-server http(s) page works even with offline mode on** (loading the document itself already established a connection to that server; browsing its folder listing is a user-initiated extension of that same trust relationship — GitHub's directory API, a different host, is not included and stays blocked while offline).
- **No tracking backend.** There is no analytics, telemetry, error-reporting or backend service operated by the extension. Preferences and confirmed search terms are stored locally. Optional PlantUML sends diagram source to your chosen server, as disclosed below; document and media requests can also reach their referenced servers.
- **Bundled rendering, documented network behavior.** All executable rendering libraries are bundled and no host permissions are requested. Online document and media loads can contact their referenced servers. Optional auto-refresh re-fetches the current document; the Files tab lists its folder on the same server, or uses the public GitHub API on raw.githubusercontent.com. A remembered Files tab can make that request again after navigating to another document. Enabled PlantUML with Offline Mode off sends diagram source to the configured server. Mermaid and ZenUML rendering do not use those servers.
- **Local directory-listing exposure, honestly disclosed.** For `file://` folders, the extension reads the browser's own native directory page through a hidden same-extension `<iframe>` (declared via a `content_scripts` entry matching `file://` directory URLs with `all_frames: true`) rather than the File System Access picker. Because that content-script entry runs in _any_ matching frame — not only ones this extension creates — a malicious local HTML file you separately open could, in principle, embed an iframe pointing at one of your folders and receive its file names, sizes, and modified times back via `postMessage`. This requires you to first open an untrusted local HTML file yourself; it never reaches the network, and it cannot read file _contents_ — only directory listings. We're not aware of a clean fix for this given `file://` pages always report an untrusted `null` origin; treat local HTML files from sources you don't trust with the same caution you would any other executable content.
- **Local settings and history only.** Preferences (theme, plugins, panel state) and confirmed search terms are stored in `chrome.storage.local` on your device, never synced to your Google account. History defaults to 10 terms; you can change its limit or clear it in settings.
- **Optional folder access.** For local (file://) documents you may grant read-only access to a folder of your choice via the browser's folder picker; the grant is stored only in this browser's local IndexedDB and can be revoked by clearing site data.
- **GitHub directory listing.** On raw.githubusercontent.com pages the Files tab lists the folder via GitHub's public API (anonymous, read-only, no token); no other data is sent.
- **PlantUML.** Off by default, and force-disabled whenever offline mode is on. When enabled with offline mode off, rendering a `plantuml` code fence — or a whole `.puml`/`.plantuml` file — sends the diagram source (your content) to the PlantUML server you configure (default `plantuml.com`; self-hostable, see docs/plantuml-server-setup.md). This is the only feature that sends document content to a third party. When off or offline, the diagram is not rendered and the source is shown as-is.
- **Residual gaps in the remote-resource sweep.** The sweep checks raw element attributes for absolute HTTP(S) and protocol-relative URLs. Relative media URLs such as `images/chart.png` or `/image.png` are retained and may load over the network on HTTP(S) pages even with Offline Mode on. CSS is not swept: inline `style="background-image:url(...)"`, `<style>`/`@import url()`, `<use xlink:href>` and legacy `background` attributes are also outside its coverage. Offline Mode is not an absolute network-isolation guarantee.
- **Permissions.** No host permission is requested; `storage` keeps your settings; `activeTab` lets the extension apply setting changes to the current tab; `offscreen` provides a bundled hidden DOM document for local Mermaid rendering when a website sandbox blocks embedded scripts. It does not grant website access or send diagram source to a server. That document is shared only during active work and closes after idle; diagram source is not persisted. File URL access (optional, off by default in Chrome) lets the extension render local files you open.
- **Network visibility.** Document loads, media, directory listings and auto-refresh may reveal your IP to the requested server. Enabled PlantUML with Offline Mode off sends diagram source to the configured server. The extension adds no tracking identifiers and has no server log. For fully disconnected operation, use a network-isolated environment and local resources.

Questions: https://github.com/swchen44/md-reader-lite/issues

Mermaid／ZenUML 使用本機封裝程式與系統字型，不連 CDN 或渲染伺服器。Mermaid 有獨立本機 frame、專用 CSP、結構化原生樣式前置檢查及 SVG/CSS 清理；資源語法遭拒時保留可讀原碼。這個 Mermaid 專用防護不代表下列既有的任意文件 HTML/CSS 清掃缺口已關閉。

GitHub raw 等沙盒頁面改由 `offscreen` 權限建立插件自己的隱藏文件，再在其中執行相同 renderer；不增加網站存取權限、不外送或儲存圖表原碼，閒置後關閉隱藏文件。正常頁面仍沿用原有 iframe。[永久驗收](docs/testing/mermaid-sandbox.md) 分開驗證沙盒繪圖與文章媒體的既有網路行為。

中文摘要：Markdown、Mermaid／ZenUML、Graphviz 與數學公式使用本機封裝程式；沒有分析、遙測或追蹤後端。設定與確認的搜尋詞存在裝置上的 `chrome.storage.local`，永不同步到 Google 帳號；搜尋歷史預設保留 10 筆，可調整或清除。離線模式預設開啟，封鎖自動刷新、GitHub API 目錄與 PlantUML，並移除支援的絕對 HTTP(S)／protocol-relative 媒體屬性。同伺服器目錄列表仍允許，文件載入本身也涉及連線。**已知限制：** HTTP(S) 文件的相對媒體網址會保留；任意文件 CSS、`<use xlink:href>`、legacy `background` 不在清掃範圍，即使離線模式開啟仍可能發出請求。這與隔離的本機 Mermaid renderer 是不同邊界。只有同時開啟 PlantUML 並關閉離線模式時，圖表原碼才送到指定伺服器。沒有 host permission；新增 `offscreen` 僅供沙盒頁面本機繪圖。本機資料夾通常由原生目錄頁讀取，失敗才使用 FSA 選擇器；任意符合的 `file://` frame 都會執行探測，因此另外開啟的不受信任本機 HTML 可能取得目錄檔名／大小／時間，不含內容、不經網路。完整斷網需隔離網路並使用本機資源，不能把離線模式當成瀏覽器防火牆。
